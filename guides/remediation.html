Remediations Guide

Intune Remediations run a detection script on a schedule and, when it reports a problem, run a remediation script to fix it.

How the pair works

ScriptExit 0Exit 1
DetectionCompliant, nothing to doProblem found, run remediation
RemediationFixedFailed

Keep Write-Output to one short status line. That’s what shows in the Intune report, and long output gets cut off.

Test before you push

On a lab device, in an admin PowerShell window:

powershell -ExecutionPolicy Bypass -File .\Detect.ps1
$LASTEXITCODE
powershell -ExecutionPolicy Bypass -File .\Remediate.ps1
$LASTEXITCODE

Scripts that run as System behave differently from your session (no mapped drives, no HKCU). To test as System, use psexec -s -i powershell from Sysinternals.

System or User

  • System (default): machine settings, services, HKLM, Program Files.
  • User: the signed-in user’s profile and HKCU. Runs only when someone is signed in.
  • Leave Run as 32-bit off unless the script needs it; 64-bit sees the real registry and Program Files.

Schedules

  • Run once: one-time fixes and cleanups.
  • Daily: drift you want corrected (settings, services).
  • Hourly: only for light, important checks. It runs on every device.

Pushing from the tool

Push creates the script package in Intune and, if you pick a group, assigns it. Right after creating, Intune sometimes rejects the assignment for a moment. The tool retries on its own, and if it still fails it offers Retry assignment. Don’t push again: that would create a duplicate.

Needs DeviceManagementConfiguration.ReadWrite.All and Group.Read.All.

Licensing

Remediations need Windows Enterprise E3/E5 or Education A3/A5 (included in Microsoft 365 A3/A5), or Windows VDA per user.

Before you deploy

  • AI-written scripts are a draft. Read every line.
  • Assign to a small pilot group first and watch the report for a day.
  • Logs go to %ProgramData%\{{logFolder}}\IntuneLogs.
