Win32 Packaging Guide

From vendor installer to Intune Win32 app: scripts, detection, settings, and the .intunewin package.

The fast path

  1. Drop the vendor’s .msi or .exe on the tool. It’s read in your browser and never uploaded.
  2. Check the fields it filled in, then Build Win32 package.
  3. Download package ZIP, extract it, and double-click Build-IntuneWin.cmd.
  4. In Intune, add a Windows app (Win32), upload the .intunewin, and copy the values from INTUNE-SETTINGS.txt.

Installer types it recognises

TypeSilent install
MSI/qn /norestart ALLUSERS=1
Inno Setup/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP-
NSIS/S (case-sensitive)
WiX Burn/quiet /norestart
InstallShield/s /v"/qn /norestart" (test first)
Advanced Installer/exenoui /qn /norestart
Setup Factory/S
Squirrel--silent (per-user only)

Anything else goes to AI, which needs a key.

Building the .intunewin by hand

IntuneWinAppUtil.exe -c .\Source -s install.ps1 -o .\Output -q

The packager in the ZIP does this for you and downloads the tool if it’s missing.

Return codes

0, 1707Success
3010Soft reboot
1641Hard reboot
1618Another install running, retry

Updating an app

  • New version = new Win32 app + Supersedence. Package content can’t be changed after upload, and don’t delete the old app.
  • Detection is version-specific (installed version is at least this package’s version), which is what supersedence needs.
  • Test in a pilot group, with a lab machine for every new installer type.
